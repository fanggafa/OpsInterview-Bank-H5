# 产品需求文档（PRD）· 运维面试题库 H5

> 版本：**v2.0**　本文档描述**当前实现的真实需求**，不是最初的规划稿。
> 架构与数据流见 [architecture](architecture.md)，出题规范见 [question-authoring](question-authoring.md)，
> 部署见 [deployment](deployment.md)，协作规范见 [conventions](conventions.md)。
>
> **维护原则**：需求变了就改这里；实现细节不进本文档。

## 一、项目概述

面向运维工程师（Linux / 网络 / 数据库 / 云原生 / DevOps）的面试题库 H5 应用，
帮助用户利用碎片时间（手机浏览器、微信内打开）刷题、背诵、自测。

| 项 | 值 |
|---|---|
| 技术栈 | Vue 3 + Vite + Vue Router + Pinia，纯 JavaScript |
| 形态 | 单页应用（SPA），移动端优先 |
| **无后端** | 无登录、无 API Key、无服务端 |
| 数据存储 | 全部在浏览器 localStorage |
| 部署 | 任意静态托管 |
| 线上地址 | https://fanggafa.github.io/OpsInterview-Bank-H5/ |

## 二、题库现状

**2892 题**：1000 简答 + 1720 单选 + 172 多选，**26 个分类**。
含 **363 张内联 SVG 图解**。

分类顺序由**业务优先级**人工指定（不是字母序），见 `src/utils/constants.js`。
每题按分类分段编号，每类预留 500 个 id，详见 [question-authoring](question-authoring.md)。

## 三、核心功能需求

### 3.1 题库浏览 `/bank`

- **分类筛选**：26 个分类，默认折叠（平铺要占 5–6 行会把列表挤到很下面）
- **频率筛选**：全部 / 高频 / 中频 / 低频
- **难度筛选**：全部 / 简单 / 中等 / 困难
- **搜索**：300ms 防抖，**只匹配题干**（标签已移出索引，见 [architecture](architecture.md)）
- **分页**：10 条/页，页码写入 URL query（刷新/后退可恢复），切换筛选重置回第 1 页
- 题目卡片显示：题干摘要（截断）、难度徽标、频率徽标、收藏星标、掌握状态
- **页头统一用 `AppHeader`**，且 `:back="false"`（题库是 TabBar 一级页，没有上一页可回）
- **题数「共 N 题」贴在搜索框最右侧**（不占页头、也不多占一行）

> 早先题库页自造了一套 `.bank-head`：左边 20px 大标题 + 右边计数。
> 全站改标题样式时它没跟着变，于是出现「只有题库页标题不对」；
> 后来又发现它多出一个返回箭头 —— 一级页面本就没有可回的地方。
> 现在统一走 `AppHeader`，计数移到搜索框尾部（搜索时顺带说明「筛出了多少题」，
> 语义比挂在页头更顺）。

### 3.2 题目详情页 `/question/:id`

- 完整题干；参考答案默认折叠、点击展开（带高度过渡）
- 标签、难度、频率、收藏按钮
- 底部「会 / 不会」自评按钮，与刷题页共用同一 store action
- **左右滑动切题**（滑到相邻 id 的题，可能跨分类，会按需补该分类的答案分片）
- id 不存在 → 404 视图

#### 滑动区要撑满，不能只有卡片那一块

滑动事件绑在 `.stage` 容器上，它必须**撑满「页头以下、提示文字以上」的剩余空间**，
用户才能在屏幕任意位置左右滑动切题。

| 要满足 | 否则 |
|---|---|
| 外层 `.page` 带 `page--fill`（纵列 flex） | flex 链在父级断开，`flex: 1` 无效 |
| `.stage` 自身 `flex: 1` | 容器高度由内容撑开，只有卡片那块能滑 |

> 用户反馈「从错题本和收藏进去的题目，卡片大小和刷题不一样，
> 导致左右滑动切换题目的区域只有卡片那一小块可用」。
>
> 根因正是上面两条：详情页的 `.page` 没带 `page--fill`、
> `.stage` 也只写了 `touch-action` 没有布局。刷题页这两条都满足，所以那边一直正常。
>
> 修复后实测：滑动区占视口 **84%**（原来是卡片那 43%）；
> 卡片下方空白区、卡片区域、贴页头的空白区**三处滑动都能切题**。

#### 滑动范围限定在来源那批题

默认按**全库顺序**前后切（题库页浏览场景）。

但**从错题本 / 收藏进来时必须限定在那一批**：

| 入口 | URL | 滑动范围 |
|---|---|---|
| 题库 / 首页 | 无 `scope` | 全库按 id 顺序 |
| 错题本 · 分类 X | `?scope=wrong&category=X` | 错题本里 X 分类的那几题 |
| 收藏 · 分类 X | `?scope=favorites&category=X` | 收藏里 X 分类的那几题 |

- 列表页的 `QuestionCard` 传 `scope` + `category`，详情页据此向 store 取对应那一批
- 切题时**必须同时保留** `scope` 与 `category`，否则切一次就退回全库
- 兜底：题刚被「连对移出」或「取消收藏」时，列表里找不到它，
  此时把当前题补进去（单元素列表），滑动自然停在原地，不会退回全库乱跳

> 用户反馈「错题本某个分类计数是 6，但进去左右滑动会切到别的分类别的题目」。
> 根因：详情页的上一题/下一题直接取 `bank.questions[index ± 1]`（全库），
> 与「错题本里的那一批」毫无关系 —— 列表页呈现的是一批，切题走的却是另一批。
>
> 修复后实测：从「错题本 · MySQL」（本分类 5 题）进详情，
> 连续左滑 6 次经过的分类**始终只有 MySQL**，
> 且最后 URL 仍带 `scope=wrong&category=MySQL`。

#### 划到边界要有提示

两端（第一题 / 最后一题）继续往外滑时，**屏幕居中弹一个轻量浮层**
（「已经是第一题 / 已经是最后一题」），**1.6 秒后自动消失**。

| 元素 | 位置 | 内容 |
|---|---|---|
| 常驻说明 | 卡片下方 | 左右滑动切换上一题 / 下一题（灰色小字，始终不变） |
| **越界浮层** | **屏幕正中** | 已经是第一题 / 最后一题（深底浅字圆角，1.6 秒后淡出） |

浮层实现要点：

| 属性 | 值 | 为什么 |
|---|---|---|
| `position` | `fixed` + 居中 | 固定在视野中心，不随页面滚动跑掉 |
| `pointer-events` | `none` | 不拦手指，提示期间照样能滑动 |
| `z-index` | 40 | 高于卡片，但不加遮罩 —— 不值得为一条 1.6 秒提示压暗整屏 |
| 过渡 | 淡入淡出 0.18s | 不能「啪」地出现，那样更像报错 |

> 用户反馈「划到最后一题再往后没有提示」。
> 早先 `go()` 里是 `if (!q) return` —— 越界时**静默返回**，界面毫无反应，
> 用户会以为手势失灵。
>
> 第一版把提示做在**底部那行小字**上（临时换文案），用户立刻反馈
> 「提示在底部，很容易忽略」—— 底部本来就有常驻说明，
> 往里换字视线根本不会落到那儿。改成**居中浮层**后才真正看得见。

#### 答案默认展开：只对收藏生效

| 入口 | 默认状态 | 为什么 |
|---|---|---|
| **收藏**（`?from=/favorites`） | **展开** | 收藏是「留一道值得反复看的题」，进来就是回顾内容，不该再点一次 |
| 题库 / 首页 / 错题本 | 折叠 | 做题 / 浏览场景；尤其首页「每日一记」要先想一想再看答案 |

- 收藏场景下**切题也保持展开** —— 用户在翻看收藏，每题都收起再让他点开没有道理
- 其他来源切题一律收起（避免边翻边看答案）

#### 折叠样式只有一份

`.answer` / `.answer__inner` / `.answer__body` 与选择题的 `.answer__key` 系列
定义在 **`src/assets/styles.css`（全局）**，详情页与刷题页共用。

> 早先这两个页面在自己的 scoped 样式里**各写了一份**，结果内边距悄悄跑偏：
> 详情页 `12px 13px`、刷题页 `11px 12px` —— 同一个「展开答案」在两个页面长得不一样。
>
> 注意：**按钮样式仍是两套**，这是有意的差异 ——
> 详情页的 `.answer-toggle` 是 44px 大条（页面里的主要操作），
> 刷题页的 `.qcard-p__toggle` 是 28px 小胶囊（题头一行里要省空间）。
> 只统一「折叠区」，不动「按钮形态」。
>
> 刷题页另有一条 `.qcard-p__scroll .answer__body { margin-top: 0 }` 局部覆盖，
> 目的是让答案紧贴题干下方、省出一行空间 —— 这是页面特定调整，保留。

#### 返回目标跟随入口（`?from=`）

顶部返回按钮**回到进来的那一页**，不是一律回题库。

| 入口 | 跳转时带 | 返回落到 |
|---|---|---|
| 首页「每日一记」 | `?from=/` | 首页 |
| 题库列表 | `?from=/bank` | 题库 |
| 收藏 | `?from=/favorites` | 收藏 |
| 错题本 | `?from=/wrong` | 错题本 |
| 未带 `from` | — | 浏览器历史回退 |

- `from` 只接受**白名单**内的路径（`/`、`/bank`、`/favorites`、`/wrong`、`/me`），
  防止被构造成任意跳转
- 详情页内左右滑动切题时**保留** `from`，否则切一道题返回目标就丢了

> **列表页自己的返回**（错题本 / 收藏）不跟随入口，固定回**首页** ——
> 它们的入口是首页「复习巩固 / 我的题集」。
> 2026-11 入口从「我的」页搬到首页后，这两个页的 `back-to` 忘了跟着改，
> 仍写着 `/me`，点返回会去一个已经没有入口的页面。

> 早先这里写死 `back-to="/bank"`，结果从**首页每日一记**点进详情后，
> 点返回跳到了题库页 —— 用户明确反馈过这条路径不对。

### 3.3 刷题页 `/practice`

**两步交互**：先选做题 / 背题，再出题卡。

| 模式 | 题型 | 判定 |
|---|---|---|
| **做题模式** | 只含选择题（单选 + 多选） | 点选项即判定；多选需点「提交答案」 |
| **背题模式** | 只含简答题 | 自评「会 / 不会」 |

#### 题卡题头**不显示**历史的「答对 / 答错」

题头只有分类 / 题型 / 难度 / 频率（以及错题连对进度、收藏按钮），
**没有**这道题「以前答对还是答错」的标签。

> 那个标签标的是**历史状态**，但题卡是答题语境：没作答时顶上写着「答错」，
> 作答后又和下方「回答正确 / 错误」并排出现 —— 两处语义打架，
> 用户会误以为「这题我刚答错了」。当前对错由结果条负责，题头不需要重复一次。
>
> **题库列表里的状态标签保留**：那里是浏览 / 筛选场景，每张卡只有一个标签，
> 用来一眼扫出哪些题答错过、哪些还没刷，没有歧义。

#### 刷新不丢（两件事都要做到）

**① 不停在「选择练习方式」**：URL 带 `started=1` 表示「已开始答题」。

- 点「做题 / 背题」开始 → 写入 `started=1`
- 刷新 → 读回 `started=1`，直接进入答题态
- 点返回退回选择页 → 从 URL 摘掉 `started`（否则刷新又被送回答题态）

**② 题目和位置也不能变**：光「留在答题页」不够 —— 队列会重新 `buildQueue`，
随机模式下等于换了一批题。用 `sessionStorage` 快照恢复题组与 cursor。

| 要恢复的 | 说明 |
|---|---|
| 题组（`ids`） | 随机队列不能重新洗牌 |
| 当前位置（`cursor`） | 停在原来那一题，不回到第 1 题 |
| 已答状态（`roundAnswers`） | 已作答的题保持原样 |

恢复条件：`review` / `mode` / `studyMode` / `category` 四项全一致，否则重抽。

> 用户原话：「刷题页面无论进哪个模式，在答题页面一刷新就自动返回到刷题页面了」，
> 随后补充：「刷新题目变了你没修，至少保证当前题目刷新不会变成别的」。
> 两件事是两个独立的 bug，都修完才算好。

**题序**：

- **默认随机**（`sequential` 保留为可选项，顶部胶囊可切）
  - 理由：固定顺序会让「每天从同一批题开始」，前面的题反复刷、后面的永远轮不到
- **断点续刷仅限顺序模式**
  - 随机队列每次重排，同一 `index` 指向的是**另一道题**，按位置恢复没有意义
  - 随机模式**既不写断点、也不显示「上次停在」提示**

**交互**：

- 卡片式单题，**吸底操作栏**
- 左右滑动切题 + 键盘 `←` / `→`
- 进度「第 n / m 题」
- 末题后展示「本轮完成」小结（对 n / 错 m / 掌握率），可「再来一轮」或「回首页」

**选择题判定后停在本题，不自动翻页**：

选择题的价值几乎全在解析里（为什么错、正确答案为什么对），1.4 秒连滚动到解析都不够。
前进的出口交给用户：吸底「下一题 →」/ 左滑 / `→` 键。
末题按钮文案是「完成本轮」，避免点「下一题」却直接结束的语义错位。

### 3.4 每日一刷 `/practice?review=dailyDrill`

**位置**：首页「每日一记」下方的**独立区块**（不属于「复习巩固」）。

- 从全库**随机抽 30 题**，**只考选择题**
- **限时 30 分钟**（顶部栏**最右侧**显示倒计时 `mm:ss`，剩余 ≤1 分钟转告警色）
- 时间到**自动交卷**：已答的照常计分，**未答的按错计入分母**
- 刷完给**分数**（= 本次正确率 0–100）与**等级**（优秀 / 良好 / 及格 / 偏弱 / 薄弱），
  并按分数段给一句**可执行**的建议（指向「回去补哪类内容」，不是空话）
- 结尾两个出口：**再来一轮**（重新抽一批，不是重放同一批）/ **退出**

#### 倒计时的两条实现要点

| 要点 | 原因 |
|---|---|
| 用「基准时刻 + 剩余值」重算，而不是每次 tick 减 1 | 浏览器切后台时定时器会被节流，逐次递减会越走越慢；用 `Date.now()` 重算切回前台立即对齐 |
| 超时交卷时**未答题计入分母** | 否则「只答 10 题且全对」会显示 100%，看似满分实则没做完 |

超时交卷时成绩单顶部会标出「⏰ 时间到，已自动交卷（未答的题按错计）」。

#### 刷新不丢（会话快照）

**答题中下拉刷新，不能换一套题、不能重置时间。**

实现：把「这一轮抽到哪些题 + 每题答了什么 + 剩余时间」写进 **sessionStorage**
（key `oi_drill_session`），`build()` 时**优先从快照恢复**，没有快照才重新抽题。

| 规则 | 原因 |
|---|---|
| 用 sessionStorage 而不是 localStorage | 关标签页就清；只有「手滑刷新」才恢复。用 localStorage 会变成跨天续做 |
| 抽完题**立刻**写一次快照 | 否则新题组要等第一次作答才保存，这中间刷新就丢题 |
| 交卷时清掉快照 | 已交卷的轮次不该被恢复，否则刷新能回到答题态、改答案 |
| 「再来一轮」**先清快照再抽题** | 否则 `build()` 命中旧快照，把「再考一次」变成「重看原题」 |
| 恢复时传剩余秒数给 `startCountdown` | 不传就白送 30 分钟 |

#### 退出要确认

答题中点顶部返回会弹**页内确认对话框**（不是 `window.confirm` —— 微信/部分安卓 WebView
下它会静默返回 `false`，表现为「点了没反应」）。

- 只有**每日一刷答题中**才弹：限时自测退出即作废，代价大；普通刷题/错题复习随时退出无损失
- **交卷后不弹**：那时退出已无损失
- 对话框显示「已答 n / 30」与「剩余 mm:ss」，主操作是「继续答题」，退出用描边红按钮
- 确认退出后清掉快照，避免下次进入又恢复这一轮

#### 答题过程中不给看答案（自测完整性）

这是每日一刷区别于其他模式的核心规则：

| 项 | 答题中 | 交卷后 |
|---|---|---|
| 「看答案」按钮 | **不渲染** | 出现 |
| 答案与解析区 | **不渲染** | 可展开 |
| 判定后「回答正确 / 错误」 | **不显示** | 显示 |

> 为什么连"对错"都不给看：能立刻知道对错，就可以退回去改答案，分数同样失真。
> 注意是**不渲染**而不是 CSS 收起 —— 收起的话 DOM 里仍有答案，等于没藏住。

**回到已答过的题必须保持原状**：选中的选项仍高亮、仍处判定态（不能再改）。
早先 `goTo` 无条件清空作答状态，导致「答完 A 进 B、回 A 时 A 变空白要重做」——
这是用户实际报过的 bug，现在由 `tests/drill.test.js` 守住。

#### 交卷后的成绩单

样式对齐「测试结果」三栏：

| 栏位 | 内容 |
|---|---|
| 正确率 | `N%` |
| 答对题数 | `对/总数` |
| 用时 | `mm:ss`（从队列生成到交卷） |

下方附**等级 + 一句建议**，再下面是**逐题回顾列表**：
每题一行（序号 / ✓或✕ / 题干摘要），**点任意一行回到该题查看解析**，
底部按钮变成「返回结果」，看完可回到成绩单。

**为什么强制选择题**：简答题靠自评，分母主观、分数没有可比性。
只有选择题点选即判、有客观对错，才撑得起「打分 + 建议」这个定位。
因此它**不跟随 URL 的 `studyMode`**，即使传了 `memorize` 也按做题模式出题。

**不写断点进度**：一次性题组，下次进来重新抽才有意义。

**首页卡片文案**：

| 位置 | 文案 |
|---|---|
| 区块标题 | 每日一刷 |
| 卡片主标题 | 30 题限时自测 |
| 卡片副标题 | 随机选择题 · 刷完给分数与建议 |

> 标题只放「这是什么」，规则细节放副标题。早先把「随机 30 题选择题」当主标题，
> 等于把规则塞进标题位、与区块标题重复，视觉上很吵。

### 3.4.1 错题复习 `/practice?review=wrong`

- 从**错题本**随机抽 10 题
- 同样不写断点、不显示顺序胶囊

> **2026-11 变更**：原「每日复习（`review=daily`，15 题全库混抽）」已被**每日一刷取代**。
> 两者都是「随机一批、直到有结论」，但每日复习混了简答题给不出可比分数，
> 价值与「连续刷」重叠；每日一刷只考选择题，定位（自测打分）才立得住。

### 3.5 错题本 `/wrong`

- **由 records 实时派生，不单独存储**
- **连对 3 次才移出**，每题显示连对进度
- **只收选择题**：由 `inWrong` 标记驱动；之后任意方式（刷题、每日一记、复习赛）
  连续答对 **3** 次才自动移出
- **两视图：分类汇总 → 点「查看」进明细**
- 返回目标 = **首页**（`back-to="/"`）

> **为什么只收选择题**：简答题靠自评「会 / 不会」，没有客观对错。
> 它进了错题本也复习不了（错题复习只从错题本抽选择题），
> 还会让薄弱分类的分母虚高。
> 因此 `mark()` 在**源头**就拦住：简答题无论怎么自评，`inWrong` 都写不进去 ——
> 这样错题本列表、错题复习、薄弱统计三个下游都自动正确，不用各自再过滤一遍。

### 3.6 收藏 `/favorites`

- 按收藏时间**倒序**（最近收藏在前）
- **只收简答题**
- **两视图：分类汇总 → 点「查看」进明细**
- 从详情页 / 刷题页星标即改即生效
- 返回目标 = **首页**（`back-to="/"`）

> **为什么只收简答题**：收藏的定位是「留一道值得反复看的题」——
> 简答题自带完整答案可读，适合反复看；
> 选择题的价值在选项里，脱离作答场景单独收进来意义不大。
>
> 因此**选择题不显示收藏按钮**（题卡、详情页、刷题页三处都按题型隐藏），
> store 的 `toggleFavorite` 也拦一道，避免以后某个页面漏删按钮又把选择题塞进来。
> 取消收藏不拦 —— 允许把历史误收的选择题清出去。

#### 两视图：先进分类汇总，再点进去看明细

与「薄弱分类」页同款：**一行一个分类，右侧「查看」才进该分类明细**。

| 视图 | 触发条件 | 内容 |
|---|---|---|
| **分类汇总**（默认） | 无 `?category=` | 每分类一行：分类名 / 题数 / 占比条 / 右侧「查看」 |
| **分类明细** | 有 `?category=X` | 该分类的题目卡 + 分页；头部有「‹」返回汇总 |

- 汇总视图的**整行是纯展示、不可点**，唯一操作是右侧「查看」
- 进度条以「题数最多的分类」为满格（用总题数做分母会让每行都短得看不出差别）
- 错题本用红色条、收藏用金色条，两页之间一眼可区分
- 用同一个路由 + query 区分两视图，而不是新增路由：退回汇总只需去掉 query

#### 分组规则（共用 `groupByCategory`）

| 规则 | 说明 |
|---|---|
| 组顺序 | 跟随 `CATEGORIES` 的业务优先级（与题库页筛选顺序一致） |
| 组内顺序 | 保持原顺序（收藏按时间倒序、错题按入本顺序） |
| 缺 `category` | 归入「未分类」，不静默丢掉 |

> 用户最初的反馈是「都没分类」；第一版做成「按分类分组的平铺列表」，
> 用户觉得还是太碎，于是改成「先进分类汇总、再点进去看明细」，
> 与「薄弱分类」页保持一致 —— 一屏内先看清「哪几类要补、各有多少」。

> **收藏页曾有个 bug**：明明已有收藏，页面上还挂着「还没有收藏」。
> 根因是 EmptyState 用了 `v-else`，它接的是上面 `v-if="confirming"` 的确认条
> 而不是 `list.length` —— 只要不在确认态，空状态就永远显示。
> 现在改成 `v-if="!list.length"` 独立判断。

### 3.7 每日一记（首页）

基于**日期种子**随机推题（无需后端），同一天进去是同一道题。

**只抽简答题**。

> 它的定位是「看一道题、记一个知识点」：简答题自带完整答案与解析，适合直接读；
> 选择题的选项在未作答时是空的，当作「每日看点」没内容可看。
>
> 早先叫「每日一题」且不限题型，抽到选择题时点开还得先做题才看得到东西，
> 与「每天来记一个知识点」的预期不符 —— 因此改名「每日一记」并限定题型。

**卡片结构**：题干是首行内容，下面是分类 / 题型 / 难度 / 频率徽标，右下角一个箭头。

> **不再写「点开作答，答完看解析」那行提示**：整张卡片本来就是按钮，
> 箭头已经说明可进，那一行既重复又白占十几像素高度。

**状态标签只在「已作答」时显示**（今天答对 / 答错、标记「会」/「不会」）。

> 未作答时**不显示**「今日一记」徽标 —— 区块标题已经写了「每日一记」，
> 再挂一个同义标签只是重复，还会把题干往下挤。
>
> **卡片里不放日期**：日期属于「今天」这个整体概念，放在 hero 标题下方。
> 早先日期挂在卡片右上角，标签去掉后那一行只剩日期，白白占掉一行高度，
> 导致题干上方一大块空白。

### 3.8 首页 `/`

**hero 主卡**：标题「运维面试题库」+ **今天的日期**（`YYYY年M月D日`）+ 副标题
（未刷过显示「碎片时间，背完这些题」，刷过显示「今天已经刷了 N 题」）+ 主题切换按钮
+ 总进度环与三个指标（已刷、简答掌握、选择正确）。

> 日期跟着**页面标题**走，不挂在「每日一记」卡片上 —— 它描述的是「今天」，
> 不是某一张卡片的属性。放在标题下方也让「每日」这个语义一眼可见。

其余区块——**按使用方式分成两个大区块**（顺序即页面顺序）：

### 背一背题（简答类）

| 卡片 | 标题 | 副标题 |
|---|---|---|
| 每日一记 | 每日一记 | **无副标题**，直接显示题干（两行截断） |

### 刷一刷题（选择类）

| 卡片 | 标题 | 副标题 |

**所有卡片共用一套骨架 `.review`**：图标 34px + 标题 14px/600 + 副标题 11px 淡色 + 行尾 chevron。区别只在**图标配色**。

| 卡片 | 图标色 |
|---|---|
| 每日一记 | 蓝紫 |
| 我的收藏 | 绿 |
| 每日一刷 | 靛蓝（试卷图标） |
| 每日复习 | 品红（循环箭头 + 对勾） |
| 错题本 | 红 |
| 薄弱分类 | 琥珀 |

> **标题为什么是「背一背题 / 刷一刷题」**：先试过「简答题 / 选择题」（题型名，像目录一样生硬），
> 又试过「背题 / 刷题」（太短、不成词），最终定成动宾结构的「背一背题 / 刷一刷题」，
> 读起来是个动作、也说明了这块要干什么。
>
> **取消了所有子标题**：早先每张卡上方还挂一行 `.section-sub`
> （「每日一记」「我的收藏」「每日一刷」「复习巩固」）。问题是——
> 要么与卡片自己的标题重复（「每日一记」上下各一次），
> 要么只是给几张卡归个类（「复习巩固」这个类别用户看不出含义）。
> 现在只有两个大区块标题 + 每张卡自己的标题。
>
> **卡片间距统一 8px**：早先「每日一刷」和「复习组」各用一个 `.reviews` 容器，
> 两个容器相邻却没有外边距，于是它们之间是 0px、组内其它卡是 8px —— 看着就是「间距不对」。
> 现在同区块的所有卡都在**一个** `.reviews` 里，共用一个 gap。
>
> **每日一记必须与其它卡对齐**：这张卡比其他卡高（多一行题干），
> 若沿用 `.review` 的 `align-items: center`，图标会被垂直居中沉到 29px，
> 而其它卡图标在 14px——一眼就能看出没对齐。
> 所以它单独 `align-items: flex-start`（图标与标题同为 14px），
> 箭头用 `align-self: center` 保持在垂直中部。
>
> **题干与图标底部齐平**：题干 `margin-top` 取 14px 是**实测量出来的**。
> 标题在 14~32px、图标在 14~48px，常规 5px 上边距会让题干停在 39px，
> 距图标底 9px，显得悬空。补足 9px 后题干顶部正好压在 48px，
> 卡片左侧形成一条整齐的边缘。
>
> **删掉了「开始练习 / 继续练习」入口卡**：它与底部 TabBar 的「刷题」重复，
> 文案还随「今天是否刷过」在「开始练习 / 继续练习」之间切换，实际点进去是同一个页面 ——
> 用户反映「没啥用」。
>
> **每日复习排在错题本上面**：每日复习是「现在就练一批」的动作，
> 错题本是「看看有哪些题要补」的清单 —— 先练再翻清单更顺手（用户要求调整）。
>
> **卡片行尾的箭头是 chevron 图标，不是文本 `→`**：文本箭头在不同字体下
> 粗细/长度不一，和卡片里的线条图标风格不搭。统一成 chevron + 淡主色圆底，
> 与 `AppHeader` 的返回箭头同一套线条语言。


### 3.9 「我的」页 `/me`

**只做数据看板**：

- 个人卡（头像 + 总进度 + 三格数字：已刷 / 错题 / 收藏）
- 掌握情况四宫格（简答掌握率 / 选择正确率 / 今日已刷 / 题库总量）
- **分类图表（折叠）**：各分类掌握度
- **设置入口只在页头右上角的齿轮按钮**

> **三格数字是纯展示，不跳转**：错题本/收藏入口搬到首页后，
> 这三格若仍链去 `/wrong`、`/favorites`，等于「我的」页又偷偷留了入口，
> 与「只做数据看板」的定位矛盾 —— 数字留在这一页，去哪儿看题由首页负责。
>
> **去掉了整行式设置入口**：页头已经有齿轮，下面再来一条「设置」是重复。
> **去掉了「我的题目」整块**：错题本/收藏本质是「题」不是「我的设置」，
> 放在首页与其他题目入口同段更好找。

**分类掌握度的排序必须与题库页的分类筛选顺序一致**（即 `CATEGORIES` 的业务优先级）。

> 早先它是按「题库遍历顺序」（实际是 id 顺序）排的，与题库页的顺序不同 ——
> 同一批分类在两个页面上的排列不一致，用户会看得很别扭。
> 现在统一以 `CATEGORIES` 为唯一顺序来源，由 `tests/me-view.test.js` 守住。

### 3.10 薄弱分类 `/weak`

- 按分类掌握率**升序**（最弱的在前），不截断，全列
- **只统计选择题**（见下）
- 每行显示「错 n · 刷 m/总数」的样本量，让人知道百分比是在多大样本上得出的
- **唯一操作是行尾的「刷错题」按钮**，进该分类刷错题

#### 统计口径：只算选择题

| 字段 | 口径 |
|---|---|
| `total` | 该分类的**选择题**总数（不含简答题） |
| `reviewed` | 刷过的选择题数（含进错题本的） |
| `wrong` | 在错题本里的选择题数 |

> **为什么排除简答题**：简答题靠自评「会 / 不会」，没有客观对错。
> 若把它算进去会有两个问题：
> ① **分母虚高** —— 简答题刷过之后 `total` 变大，33% 门槛跟着抬高；
> ② **语义混乱** —— 自评「不会」并不等于「这题做错了」。
>
> 错题本已限定只收选择题，所以 `wrong` 天然只来自选择题；
> 但 `total` / `reviewed` 仍要显式过滤一遍，否则简答题的刷题记录会把分母撑大。

#### 布局：一块列表，每行一行信息

| 区域 | 内容 | 可点？ |
|---|---|---|
| 左 | 分类名 + 样本量（错 n · 刷 m/总数） | ✗ |
| 中 | 错误率条 | ✗ |
| 右 | 百分比 | ✗ |
| 行尾 | **「刷错题」**文字胶囊按钮 | ✓ |

> **整行是纯展示，不可点**。走过两个弯路，都被用户否掉：
>
> ① 每张卡底部塞两个 44px 实心按钮 → 26 个分类整页 **4199px（4.7 屏）**，
> 用户：「下滑半天才到底部」。
> ② 改成整行可点直接开刷 → 用户：「点左边文字和进度条跳到刷题页感觉很奇怪」。
> ③ 整行可点进题库 → 用户：「整行就显示这个进度条不行吗，非得跳转」。
>
> 最终：**数据展示就是展示，本页只有一个操作 ——「刷错题」**。
> 也不用小图标替代文字（用户：「图标看不清也看不明白」）。
>
> 收成「一块列表 + 细分隔线」（不是 26 张各自带阴影的卡片），单行 **55px**，
> 26 个分类整页从 4199px 降到 **约 1636px（1.8 屏）**。

#### 参赛门槛：刷满该分类的 33%

一个分类需**刷过它题量的 33%**（下限 3 题）且**含错题**，才参与排行。

| 分类题量 | 需要刷 | 说明 |
|---|---|---|
| 100 题 | 33 题 | 33% |
| 32 题 | 11 题 | 33% |
| 6 题 | 3 题 | 33% 只有 2 题，取下限 3 |

**为什么按比例而不是固定 3 题**：3 题在 100+ 题的分类里只占 3%，
刷三道全错就把整个分类判成 100% 薄弱，结论站不住。按比例才有可比性。

**为什么仍保底 3 题**：极小分类若只有 6 题，33% 是 2 题 —— 2 题的样本同样不可信。

数据不足时 `/weak` 给空状态说明，而不是硬排一个结论。

**首页入口卡常驻**：无数据时显示引导文案
（「数据还不够 · 同分类刷满它题量的 33% 且含错题后开始排行」）且可点进 `/weak`。

> 早先的做法是「无数据时整卡隐藏」，结果是用户以为这个功能没了。
> 现在与「错题复习」卡保持一致：**卡片永远在，只是没数据时不给结论**。

### 3.11 设置页 `/settings`

按「每天要看」与「偶尔才改」把「我的」拆开：

- 外观主题（三态）
- 清空数据（需二次确认）
- **安装到桌面**（安装引导，见下）
- 关于

#### 安装引导

一个可展开的说明区块，**按平台自动给出对应步骤**（`src/utils/installGuide.js`）。

已处于独立形态运行时（`display-mode: standalone` 或 `navigator.standalone`），
只显示「已装好」而不再给步骤。

> **为什么安卓把「自带浏览器」放第一位**：Chrome 的「安装」不在本机完成 ——
> 它把站点上传到 Google 服务器铸 WebAPK 再下载回来。国行设备即使有 GMS，
> 也常因连不上 Google 而静默失败（实测：弹「正在安装…」后消失，产出 `.mht`，
> 桌面与应用抽屉均无图标）。自带浏览器是本机直接建快捷方式，绕过全部外部依赖。
>
> 取舍：快捷方式路径会带浏览器地址栏（非全屏），但**离线能力同样具备**。

### 3.12 夜间模式

- `settings.theme` 三态 `light | dark | system`（默认 `system`）
- 跟随 `prefers-color-scheme` 并在系统变化时实时响应
- 手动切换后持久化；`<html data-theme>` 驱动 CSS 变量
- 切换时同步更新 `<meta name="theme-color">`

### 3.13 PWA 离线

**已实现**：全量预缓存 + 手动更新提示。目标场景是**通勤/地铁没网时也能刷题**。
实现细节见 [deployment](deployment.md)。

### 3.14 答案插图

部分简答题的参考答案带**内联 SVG 图解**，用 `[[图:id]]` 引用。
完整规范见 [figure-authoring](figure-authoring.md)。

## 五、题型与判定

| 题型 | 判定方式 | 记录状态 |
|---|---|---|
| 简答 `short` | 用户自评 | 会 / 不会 |
| 单选 `single` | 点选项即判 | 答对 / 答错 |
| 多选 `multiple` | 点「提交答案」，**全对才算对** | 答对 / 答错 |

- 判定结果**统一映射到 `know` / `unknown`**，所以错题本、今日已刷数无需按题型特殊处理
- 答错的选择题**会**进入错题本
- **掌握率只统计简答题**，选择题单独算正确率（两者的「会」含义不同）

4. `QuestionView` / `PracticeView` 加渲染分支（两者结构一致）

## 六、UI / UX 要求

### 移动端密度规范

**布局基准是「手机满屏密度」**（桌面端仍 480px 居中）。

- 页面左右留白 12px；卡片内边距 12~14px；卡片间距 8px
- 正文字号：题干 16px（简答）/ 15px（选择题），答案 13px，辅助文字 12px，最小不低于 11px
- 列表页一屏目标：375×667 下至少可见 4 张题卡
- **列表必须分页，不允许无限滚动**
  - 10 条/页，超过一页才显示分页控件
  - 分页控件吸底固定
  - 页码写入 URL query；切换筛选重置为第 1 页
  - 条目减少导致页码越界时自动收敛
- **刷题页沉浸式布局**：卡片区占满「顶栏以下、操作栏以上」高度，
  题干与答案在卡片内部滚动；操作栏 `position: sticky` 吸底
- 底部安全区：吸底容器统一 `padding-bottom: max(12px, env(safe-area-inset-bottom))`
- 触摸目标不小于 44×44px

### 视觉规范

| 项 | 值 |
|---|---|
| 风格 | 简洁、工具感 |
| 主色（浅色） | `#4F7CFF` |
| 主色（深色） | `#6E93FF`（保证小字号对比度 ≥4.5:1） |
| 浅色背景 / 卡片 | `#F6F7FB` / `#FFFFFF` |
| 深色背景 / 卡片 | `#121212` / `#1E1E1E` |
| 圆角 | 12px |
| 难度色 | 简单 `#52C41A`、中等 `#FAAD14`、困难 `#F5222D` |

- 主题通过 `<html data-theme>` + CSS 变量实现，**禁止在组件里写死颜色值**
- 频率徽标用中性灰蓝，不抢难度视觉
- 移动端以 375px 设计；iOS 安全区 + `viewport-fit=cover`
- 桌面端内容区最大宽度 480px 居中
- 空状态（无收藏 / 无错题 / 无搜索结果 / 加载失败）：内联 SVG 小插画 + 引导文案 + 行动按钮
- 无障碍：点击区 ≥44px、按钮有 `aria-label`、`prefers-reduced-motion` 时关闭动画

## 八、明确不做（已剔除，不再作为待办）
